# AM32 on the OpenAIO Base (4x AT32F421G8U7 + NSG2065Q)

Sources:
- am32-firmware/AM32 `50234143` (firmware 2.21, `Inc/version.h`)
- am32-firmware/AM32-bootloader `578ff29c` (bootloader version 19, `Inc/version.h`)
- OpenAIO netlist at `be152bb`

Pin-by-pin evidence is in `PINOUT.md`, section "ESC MCUs".

## Target

**Use `OPENESC_20_F421`** for all four ESCs (`Inc/targets.h:2121-2129`). Its definition:
- `HARDWARE_GROUP_AT_B`: input PB4 on TMR3_CH1; phases A = PA10/PB1, B = PA9/PB0, C = PA8/PA7. See `Inc/targets.h:4889-4922`.
- `HARDWARE_GROUP_AT_045`: comparator PA0/PA4/PA5, with PA1 as the common. See `Inc/targets.h:5101-5105` and `Mcu/f421/Src/peripherals.c:77`.
- `NO_VOLTAGE_SENSE`, `NO_CURRENT_SENSE`, `DEAD_TIME 60`.

`OPENESC_30_F421` (`:2111-2119`) has the same definition and differs only in `FIRMWARE_NAME`. The 20 matches the 20 A per-motor design point (PLAN D5).

**Why not the other AT_B targets:** the AT32DEV, FLYWOO and TBS variants enable voltage or current sense on PA3/PA6. Those pins are not connected on this board.

## Pin overrides

**None.** All four ESCs are wired identically, and every pin matches the target:
- **Input.** PB4 (pin 25) is the input, reached from `MOTORn` through 220R.
- **Gate driver.** PA10/PA9/PA8 drive HIN1/HIN2/HIN3 (NSG2065Q pins 22/23/24) of U14/U16/U18/U20. PB1/PB0/PA7 drive LIN1/LIN2/LIN3 (pins 1/2/3).
- **Driver polarity.** NSG2065Q inputs are in phase, VIH 2.5 V (NSG2065Q.pdf p4, p6). The target sets no `USE_INVERTED_*` option, which is correct.
- **Back-EMF.** The dividers are 10k/1k from each phase to PA0/PA4/PA5. A 3 x 10k virtual neutral goes to PA1.

**Motor direction** is set per ESC in the AM32 settings ("Motor direction reversed"). Any phase-to-wire order works.

## Flashing paths

### 1. First flash of a blank AT32 (factory parts): SWD, once per ESC

**Pads:**

| ESC | SWDIO (PA13) | SWCLK (PA14) |
|---|---|---|
| ESC1 (U13) | TP1 | TP2 |
| ESC2 (U15) | TP3 | TP4 |
| ESC3 (U17) | TP5 | TP6 |
| ESC4 (U19) | TP7 | TP8 |

- GND can be taken from any GND pad.
- There is no NRST pad and no per-ESC VTref pad (ISSUES I18), so attach without reset. That works because AM32 never remaps PA13/PA14.

**Power:**
- At `be152bb`, the AT32 VDD is +3V3 from U23, fed from +4v5. USB power alone therefore powers the ESC MCUs.
- After the planned battery-only ESC rail (owner decision, see ISSUES I3), SWD flashing needs battery power. Use a current-limited supply or a smoke stopper.

**Procedure:**
1. Use an SWD probe that supports the AT32F421 (for example Artery AT-Link, or a probe with Artery's device pack).
2. Flash `AM32_F421_BOOTLOADER_PB4_V19.hex`.
3. Optionally flash `AM32_OPENESC_20_F421_2.21.hex` in the same session.

### 2. Firmware install, updates and settings: Betaflight 4-way passthrough

- **Support.** Betaflight's RP2350 platform supports BLHeli/AM32 4-way passthrough over the motor pins (`src/platform/PICO/target/common/target_RP2350.h:144-147`).
- **Tools.** ESC Configurator (or AM32 Configurator) connects through the FC's USB.
- **Power.** The battery must be connected so the ESCs and the gate drivers are powered.
- **Bootloader.** The AM32 bootloader listens on PB4, the same pin as DShot, so no extra wiring is needed.

### 3. Recommended settings

- **Bidirectional DShot.** AM32 detects it automatically. `config.h` sets `DEFAULT_DSHOT_TELEMETRY DSHOT_TELEMETRY_ON`.
- **No ESC-level protection.** With no voltage or current sense, AM32 low-voltage cutoff and current limiting are unavailable. Use Betaflight's battery monitoring: VBAT on GPIO29, board current on GPIO28 from the INA186A3.

## Board issue that touches AM32

**I3 (MAJOR, fix planned, not yet in the netlist):** on USB power alone, the AT32s are powered while the NSG2065Q VCC (+10V) is at 0 V.

AM32 plays its startup tune unconditionally on the AT421 (`Src/main.c:1893`). The tune drives the phases through `comStep()` even when a custom tune is stored (`Src/sounds.c:118-142`), so no AM32 setting avoids it.

The owner-approved fix is a battery-only 3.3 V LDO for the four AT32s. Until it lands, avoid plugging USB in without a battery on boards that have the ESCs populated.
